# ラク経費 サーバー版（会計ソフト化）の構成と見積

2026年11月時点の案です。金額は目安なので、契約の前に各サービスの料金ページで確かめてください。

## 1. なぜサーバーが必要か

いまのラク経費は、データを各パソコンのブラウザの中だけに保存しています。会計ソフトとして使うには、次のことがこの形ではできません。

| やりたいこと | いまの限界 | サーバーで解決すること |
|---|---|---|
| データを失わない | ブラウザのデータを消すと全部消える | サーバーの DB が正本。自動バックアップと、過去の時点への復元 |
| 何人かで使う（経理・社員・税理士） | 1 台ずつ別のデータ。同期フォルダは 1 人向け | ログインと権限。全員が同じデータを見る |
| 承認 | ファイルを渡すだけで、本人確認も改ざん防止もない | 申請・承認・差し戻しを、誰がいつ行ったかの記録つきで管理 |
| 電子帳簿保存法 | 履歴を同じブラウザに置くので消せてしまう | 消せない保存場所に、改ざんを検知できる形で履歴を残す |
| 締め | いつでも過去を直せる | 月次・年次の締めで、過去の仕訳をロックする |
| AI 読み取り | API キーを各ブラウザに置く | キーはサーバーだけに置き、使った量を管理する |

## 2. 全体の構成

```
[ブラウザ（いまの画面を流用）]
   │  ログイン（メール・Google）
   │  HTTPS
   ▼
[API サーバー] ── [PostgreSQL（正本・行単位の権限）]
   │             └ 毎日のバックアップ ＋ 過去の時点への復元（PITR）
   ├── [ファイル保存（領収書の画像・PDF・メール）] … 消せない設定（オブジェクトロック）
   ├── [読み取り（AI）] … API キーはここだけ
   ├── [メール送信] … 承認依頼・差し戻し・期日超過のお知らせ
   └── [監視・エラー通知・ログ]
```

- **画面はいまのものを使います**（ES モジュールの PWA）。保存先の `store.js` だけを「サーバーの API ＋ 端末のキャッシュ」に入れ替えます。オフラインで入れた分は、つながったときに送ります。
- 帳簿の計算（`books.js`・`finance.js`・`assets.js`・`exports.js`）は端末に依存しないので、同じコードをサーバーでも動かせます（Node.js）。

## 3. 必要なもの

### 3-1. サービス・インフラ（3 つの選び方）

| | A. まとめて借りる（おすすめ） | B. 自分の VPS | C. AWS で本格的に |
|---|---|---|---|
| 中身 | Supabase（PostgreSQL・ログイン・ファイル保存・行単位の権限が 1 つに入っている） | VPS 1 台に Node.js ＋ PostgreSQL。ファイルは S3 互換ストレージ | ECS / Lambda ＋ RDS ＋ S3 ＋ Cognito |
| 作る量 | いちばん少ない（ログイン・権限・ファイルを作らなくてよい） | ログイン・バックアップ・更新を自分で作り、運用する | 多い。設計の自由度は最大 |
| 運用の手間 | 小 | 大（OS 更新・DB のバックアップ・障害対応） | 中〜大 |
| 月額の目安（小さく始めたとき） | 約 4,000〜8,000円（Pro プラン $25 ＋ 使った分） | 約 2,000〜6,000円（VPS ＋ ストレージ） | 約 15,000〜40,000円 |
| 向いている規模 | 〜数百社・数千人 | 自分の会社だけ・数十人 | それ以上・大企業向け |

**おすすめは A** です。いちばん手間のかかるログイン・権限・バックアップを自前で作らずに済み、会計の中身に時間を使えます。あとで B・C に移ることもできます（PostgreSQL なのでデータはそのまま移せます）。

### 3-2. そのほかに必要なもの

| もの | 用途 | 費用の目安 |
|---|---|---|
| 独自ドメイン | `keihi.example.jp` など | 年 1,500〜4,000円 |
| メール送信サービス（Resend・Amazon SES など） | 承認依頼・お知らせ | 0〜3,000円/月 |
| エラー監視（Sentry など） | 不具合にすぐ気づく | 0〜4,000円/月 |
| Claude API | AI 読み取り・文章で仕訳 | 1 枚数円。月 1,000 枚で数千円 |
| 認定タイムスタンプ（任意） | 電帳法の「スキャナ保存」を厳しく満たすとき | 月数千円〜（事業者による） |
| 外部の脆弱性診断（公開前に 1 回） | お金のデータを扱うので推奨 | 30万〜100万円（1 回） |
| 利用規約・プライバシーポリシー | 他社に提供する場合は必須 | 自作なら 0。弁護士の確認で 10万〜30万円 |

### 3-3. 法律・制度で気をつけること

- **個人情報保護法**: 氏名・口座・取引先などを預かるので、安全管理措置・委託先（クラウド）の管理・漏えい時の報告の体制が要ります。
- **電子帳簿保存法**: 「訂正削除の履歴が残る」か「訂正削除ができない」保存が必要です。サーバー版では、履歴を追記だけの表にし、前の記録のハッシュをつなげて改ざんを検知します。ファイルは消せない設定のストレージに置きます。JIIMA 認証は必須ではありませんが、他社に売るなら取ると安心です（申請費用・期間がかかります）。
- **銀行の API で明細を自動取得する場合**: 利用者の代わりに銀行 API を使うには「電子決済等代行業」の登録と、各銀行との契約が必要です。個人で作るなら、当面は **CSV の取り込みを続ける**か、登録済みの集約サービス（Moneytree LINK など）と契約する方が現実的です。
- **e-Tax への直接提出**は仕様が大きく、今回の見積には入れていません（決算書の数字を e-Tax の画面に写す形を続けます）。

## 4. 作るもの（データの形）

| 表 | 中身 |
|---|---|
| organizations / members | 会社（事業者）と、所属する人・役割（申請者・承認者・経理・管理者・税理士閲覧） |
| expenses / receipts | 経費と、領収書のファイル（保存場所・ハッシュ・受け取った日時） |
| ledger_entries | 売上・振替・外注費・請求書 |
| journal_entries / journal_lines | **保存する仕訳**（いまは毎回つくり直しているのを、確定した仕訳として保存。複合仕訳・補助科目・部門に対応） |
| periods | 会計期間と月次・年次の締め（締めた期間は直せない） |
| fixed_assets / budgets / sites / vehicles / recurring_rules | 固定資産・予算・現場・車・毎月の自動登録 |
| reports / approvals | 精算と承認の流れ（申請 → 承認・差し戻し → 支払い） |
| audit_log | 変更の履歴（追記だけ・前の行のハッシュつき） |
| settings | 事業者ごとの設定（帳簿の形・消費税・発行元など） |

権限は DB の行単位で付けます（Supabase の RLS）。「自分の会社の行だけ見える」「申請者は自分の経費だけ直せる」などを DB 側で強制するので、画面のバグがあっても他社のデータは見えません。

## 5. 作業の見積

**1 人日 = 1 人が 1 日（8 時間）**。「外注」は 1 人月（20 人日）あたり 60万〜100万円で計算しています。

| # | 作業 | 内容 | 人日 |
|---|---|---|---|
| 1 | 設計 | データの形・権限・締め・同期のしかた・画面の流れ | 8 |
| 2 | 基盤 | Supabase（または VPS）・ドメイン・本番 / テスト環境・自動デプロイ | 4 |
| 3 | ログイン・会社・権限 | メール / Google ログイン・2 段階認証・招待・役割 | 8 |
| 4 | データを DB へ | 表・権限ルール・いまの端末データの移行ツール | 12 |
| 5 | 画面の保存先を入れ替え | `store.js` を API ＋ 端末キャッシュに。オフラインで入れた分の送信 | 12 |
| 6 | ファイル保存 | 領収書・PDF・メールのアップロード、消せない設定、サムネイル | 5 |
| 7 | AI 読み取りをサーバーへ | キーをサーバーだけに。使った量の記録・上限 | 4 |
| 8 | 仕訳の保存と締め | 仕訳を確定して保存・月次 / 年次の締めとロック・補助科目・部門 | 15 |
| 9 | 承認の流れ | 申請・承認・差し戻し・メール通知・承認者の設定 | 8 |
| 10 | 電帳法の強化 | 追記だけの履歴（ハッシュの鎖）・検索の要件・保存期間 | 6 |

### 段階に分けた場合

| 段階 | 内容（上の番号） | 人日 | 外注した場合 | できるようになること |
|---|---|---|---|---|
| **1. 自分の会社で使う** | 1〜7・11 の一部・12 の一部 | 約 55 | 約 170万〜280万円 | ログインして、どのパソコン・スマホでも同じデータ。データが消えない。AI キーを配らなくてよい |
| 2. 社内で回す | 9・10 | 約 15 | 約 45万〜75万円 | 本当の承認の流れと、電帳法に強い履歴 |
| 3. 会計ソフトとして仕上げる | 8・11 の残り | 約 30 | 約 90万〜150万円 | 仕訳の確定・締め・補助科目・部門。税理士に渡せる帳簿 |

**自分で作る場合**（Claude と一緒に作る前提）は、上の人日がそのまま作業時間の目安です。平日夜と週末に作業するなら、段階 1 が **約 2〜3 か月**、全部で **約 6〜8 か月** です。

## 7. 進め方の提案

1. **段階 1 から始める**（Supabase）。いまの画面はほぼそのまま使い、保存先だけをサーバーにします。まず自分の会社だけで 1〜2 か月使います。
2. 使いながら、段階 2（承認）・段階 3（締め・補助科目）を足します。
3. 他社に提供するかは、段階 3 まで使ってから決めます（規約・診断・サポートの費用が別にかかるため）。

始めるときに決めること:

- 使う人数と役割（申請するだけの人・承認する人・経理・税理士）
- 個人事業主だけか、法人も対象か（法人なら締めと補助科目が先に必要）
- 自分で運用するか、外注するか
- いまの端末のデータを移すか（移行ツールで移せます）
